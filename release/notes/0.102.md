## 0.102

0.102 is the largest release of devrig and MCP Steroid to date — 535 commits touching both halves of the product. **devrig**, the CLI you install and run, grows one unified command surface where every `steroid_*` MCP tool is a subcommand generated from its own schema, keeps itself up to date automatically, installs the MCP Steroid plugin into your running IDEs for you, downloads fourteen JetBrains IDE products, and can bootstrap a headless Remote Development backend entirely from an agent session. **The MCP Steroid plugin**, in turn, compiles `steroid_execute_code` scripts roughly 3× faster with an in-process Kotlin compiler, returns machine-parseable results, is ready for IntelliJ 2026.3 EAP, loads on Android Studio, and picked up a long list of correctness, modality, and Windows fixes.

> **`devrig` is the recommended entry point.** Direct use of the MCP Steroid plugin's HTTP server is still supported (and now explicitly marked deprecated in the settings UI), but `devrig` owns installation, the Java runtime, agent registration, updates, and backend lifecycle — there is far less to set up and keep in sync.

> **Independent project.** MCP Steroid / Devrig is an independent open-source project. It is **not affiliated with, sponsored by, or endorsed by JetBrains.**

### Breaking changes

Two intentional breaks, both with documented migrations:

- **The `applyPatch { }` script DSL is removed** ([#206](https://github.com/jonnyzzz/mcp-steroid/issues/206), [#209](https://github.com/jonnyzzz/mcp-steroid/issues/209)). At eval scale it failed 64% of invocations, so it is gone in favor of the taught single-`writeAction` multi-edit recipe plus a new apply-unified-diff escape hatch built on the IDE's own patch engine (with recipe test coverage) — file edits now go through documented IntelliJ APIs instead of a bespoke helper.
- **`steroid_list_windows` renames `projectName` / `projectPath` to snake_case `project_name` / `project_path`** ([#381](https://github.com/jonnyzzz/mcp-steroid/issues/381)), matching `steroid_list_projects`, the sibling `backend_name` key, and the tool's own documentation. Consumers that read the old camelCase keys must switch.

### One devrig CLI, generated from the tools' own schemas

Phase B of [#284](https://github.com/jonnyzzz/mcp-steroid/issues/284) landed: every `steroid_*` MCP tool is now a first-class devrig subcommand **auto-generated from its own schema metadata** — adding a tool adds its command with no hand-written parser code, and the served stdio MCP surface registers from the same canonical `devrigToolSpecs()` list, so the CLI and the MCP server can never drift ([#437](https://github.com/jonnyzzz/mcp-steroid/issues/437), [#356](https://github.com/jonnyzzz/mcp-steroid/issues/356)); a golden test pins the MCP wire unchanged.

- **One Clikt tree for everything** ([#442](https://github.com/jonnyzzz/mcp-steroid/issues/442)): all commands share consistent help, aliases, and error handling, replacing the hand-rolled help command and per-command argument code. Project listing is canonical `list_projects` with a dedicated console renderer — `projects` and `project` stay as compatibility aliases.
- **Help that routes you** ([#450](https://github.com/jonnyzzz/mcp-steroid/issues/450), [#454](https://github.com/jonnyzzz/mcp-steroid/issues/454)): `devrig --help` is a compact command index again; the full ~90-line tool reference moved to the new `devrig tools` page written for coding agents; `devrig help <tool>` offers layered follow-up reading (`execute_code` links its guide articles); `devrig prompt <uri>` takes the URI as a bare positional. Missing or invalid parameters route to focused help with the exact allowed values instead of a generic usage dump — and parse validation happens **before** any backend, file/stdin, or `--out` side effect.
- **Exit codes follow sysexits** ([#437](https://github.com/jonnyzzz/mcp-steroid/issues/437), [#450](https://github.com/jonnyzzz/mcp-steroid/issues/450)): parse errors aggregate into one `USAGE=64` message, internal faults exit `SOFTWARE=70` with a stderr trace, and only `IOException` maps to `UNAVAILABLE=69` — a devrig fault is distinguishable from your typo and from an unreachable IDE.
- **`--json` and `--out` you can build on**: under `--json` a tool's JSON payload is a real `content[].json` object (no more double-decoding for jq) with a shared `{tool, command, isError, data}` envelope; `--out` is accepted only on the tools that can actually produce an image and writes atomically; stdin and `--*-file` sources reject malformed UTF-8, binary bytes, and inputs over the 10 MiB cap.
- **`open_project --wait` genuinely waits**: it polls `list_windows` until the project is initialized, not indexing, and dialog-free (5-minute deadline), returns the fresh `project_name`, `backend_name`, and canonical path — and a *failed* open surfaces its own error immediately instead of polling for 300 seconds.
- devrig-authored text translates `steroid_*` names into runnable devrig commands, while tool result payloads stay verbatim; `--help` also stops promising a cwd inference of `project_name` that no code performs.
- The whole surface is recorded as an authoritative contract in `docs/devrig-cli-contract.md` ([#452](https://github.com/jonnyzzz/mcp-steroid/issues/452)), and pinned by unit tests, a stable real-IDE Docker flow ([#450](https://github.com/jonnyzzz/mcp-steroid/issues/450)), and live Claude/Codex agent-usability experiments ([#442](https://github.com/jonnyzzz/mcp-steroid/issues/442)).

### devrig keeps itself up to date

devrig now auto-updates ([#270](https://github.com/jonnyzzz/mcp-steroid/issues/270), [#380](https://github.com/jonnyzzz/mcp-steroid/issues/380)): when the published `version.json` promotes a newer version, running sessions download and run the official `install.sh` / `install.ps1`, coordinated across concurrent devrig processes via per-pid marker files, with restart notices and SNAPSHOT/env-var opt-outs. Several review rounds simplified the design to something deliberately boring — **no lock files, no failure-count state** (failures retry quietly on the jittered 3–8 h schedule), an opaque installer capped at one hour, lower-pid-wins race resolution, and a stdout-purity test guarding the MCP channel ([#373](https://github.com/jonnyzzz/mcp-steroid/issues/373), [#268](https://github.com/jonnyzzz/mcp-steroid/issues/268) closed by this coordination design). A telemetry beacon fires exactly once per actually-triggered update.

- **Launcher replacement survives Windows file locks** ([#385](https://github.com/jonnyzzz/mcp-steroid/issues/385)): the `~/.mcp-steroid/bin/devrig` launcher is replaced via a rename-based, rustup-style sequence, fixing the silent self-heal no-op while cmd.exe or an antivirus holds the launcher open — validated by Windows-only tests under real NTFS contention (an executing cmd.exe, a memory-mapped holder, a no-delete-share holder).
- **An older devrig never overwrites a newer launcher** ([#374](https://github.com/jonnyzzz/mcp-steroid/issues/374)): generated launchers carry a machine-parseable version header checked during self-heal.
- **Version numbers finally compare correctly** ([#360](https://github.com/jonnyzzz/mcp-steroid/issues/360), [#358](https://github.com/jonnyzzz/mcp-steroid/issues/358)): all build lanes share one token layout, `<base>.<counter>-<lane>-<hash>`, with releases as `<base>.0-r-<hash>`, so IDE version comparison never depends on whether a git hash starts with a digit. Behind it, IntelliJ Community's `VersionComparatorUtil` is ported into mcp-core (repackaged under Apache 2.0 with the NOTICE shipped in both distributions) and wrapped in a `Comparable` Version type tested against the repo's real version history — update notifications for both the plugin and devrig now fire only when the promoted version actually precedes the current build, ending false update nags.
- Advancing the `website` branch — the devrig auto-update rollout trigger — is now gated on `release/scripts/verify-release-ready.sh`, which verifies the published GitHub release carries the correctly-named plugin/devrig zips and EULA.

### `steroid_execute_code` compiles in-process — roughly 3× faster

The fixed per-call Kotlin compiler startup — an average of **7.8 seconds, 94% of wall time** — is gone ([#207](https://github.com/jonnyzzz/mcp-steroid/issues/207)). Snippet compilation moved off the kotlinc subprocess onto the **Kotlin Build Tools API** with one shared build session per project ([#361](https://github.com/jonnyzzz/mcp-steroid/issues/361), ~15 s vs ~25 s across 18 real compilations), and by the end of the window the Kotlin daemon machinery is gone too: compilation runs fully in-process, with the kotlin-compiler-runner and kotlin-daemon-client jars pruned from the bundle (12→10 jars) and a stability suite pinning the single in-process flow. **The plugin no longer downloads a kotlinc distribution at all** — the compiler jars ship as real files in a top-level `kotlinc/` folder of the plugin distribution.

- Pinning the compiler application environment per session cuts warm compiles from 367 ms to 218 ms (BTA 2.4.10 otherwise re-parses all ~1800 classpath jars on every compile); the shared-session trick also halves the KtBlock CI matrix.
- Compiler messages are structured, remapped to user-code coordinates, and persist even through timeouts and OOMs — a compile timeout now surfaces as a real "stopped on timeout" failure instead of a spurious cancellation.

### Ready for IntelliJ 2026.3 EAP and Android Studio

- The bundled kotlinc is bumped **2.3.20 → 2.4.10** so `steroid_execute_code` works on IntelliJ 2026.3 EAP (which ships Kotlin 2.5.0 metadata) while staying compatible with 2026.1 and 2026.2 ([#357](https://github.com/jonnyzzz/mcp-steroid/issues/357), [#359](https://github.com/jonnyzzz/mcp-steroid/issues/359)). When an attached IDE's metadata does outrun the bundled compiler, the plugin now fails fast with a single actionable message instead of hundreds of cryptic compile errors ([#377](https://github.com/jonnyzzz/mcp-steroid/issues/377)).
- Scripts now default to **Kotlin language/API level 2.3** (up from 2.2) — the floor of the supported IDE range — unlocking Kotlin 2.3 language features and stdlib API in your scripts.
- The plugin and devrig now emit **JVM 21 bytecode** (while keeping the JDK 25 toolchain), so they load on Android Studio's bundled JBR 21 where v0.101 failed with `UnsupportedClassVersionError` ([#157](https://github.com/jonnyzzz/mcp-steroid/issues/157), [#181](https://github.com/jonnyzzz/mcp-steroid/issues/181), [#182](https://github.com/jonnyzzz/mcp-steroid/issues/182), [#184](https://github.com/jonnyzzz/mcp-steroid/issues/184)). A class-file version guard scans every class the plugin ZIP and devrig dist ship — recursing nested jars and honoring multi-release-JAR overlays — and an Android Studio 261 Docker gate exercises `list_projects`, `list_windows`, and `execute_code` against the production plugin.

### `steroid_execute_code` output is machine-parseable again

The tool result is now exactly the `execution_id:` header plus your script's own printed output — the `[PRE]` / `[RUN]` / `[POST]` stage framing and in-flight progress lines no longer interleave with the payload, so a script that prints a single JSON document parses again ([#154](https://github.com/jonnyzzz/mcp-steroid/issues/154), [#159](https://github.com/jonnyzzz/mcp-steroid/issues/159)). The progress didn't disappear: every stage line goes to `idea.log`, to MCP **progress notifications** when your client passes a `progressToken`, and to the execution event log; failing pre-flight steps are named with their original exceptions propagated untouched.

- Successful compiles stop forwarding kotlinc's DEBUG-severity boot chatter, and `-Xdisable-default-scripting-plugin` removes the spurious "Scripting plugin will not be loaded" noise — fewer wasted agent tokens per call. Successful calls also no longer spam stderr with a scripting-plugin `ClassNotFoundException` and a 45-entry JDK module dump ([#463](https://github.com/jonnyzzz/mcp-steroid/issues/463)).
- **The print-only output contract is taught everywhere**: all agent-facing docs and the served tool description now lead with the fact that only *printed* output is returned — a bare trailing expression is ignored — so scripts must end with `println`/`printJson`; every copy-paste recipe ends with a print, and the wrong/right example covers the `return results` mistake.
- `printToon`'s docs now describe its actual two-form contract: uniform key sets get the compact table encoding, ragged records fall back to a per-element block ([#459](https://github.com/jonnyzzz/mcp-steroid/issues/459)).

### The host IDE's identity is back in `list_projects` / `list_windows`

Both list tools now carry a `backends[]` lookup — one element per referenced backend, sorted by `backend_name` — resolving each entry's `backend_name` to the host IDE's identity ([#155](https://github.com/jonnyzzz/mcp-steroid/issues/155)):

```json
"backends": [
  { "backend_name": "iu-47qi79c1",
    "intellij": { "name": "IntelliJ IDEA 2026.1.3", "version": "2026.1.3", "build": "IU-261.25134.95" } }
]
```

Entries keep only their `backend_name` key (identity appears once per response, never per entry), `projects[]` are sorted by `project_name`, and a direct in-IDE server always includes its own entry — so a fresh IDE with zero open projects is still identifiable with one cheap tool call, no kotlinc round-trip. **Migration:** parsers that read the old top-level `ide.*` should switch to `backends[0].intellij`. devrig's `project` / `backend` text and `--json` output now carry the same identity keys in the same order as the MCP responses.

### `steroid_execute_code` reliability and IDE responsiveness

- Every execution now runs as a **visible, cancellable "devrig — MCP Steroid task"** in the IDE status bar, and a client disconnect cancels the script via structured concurrency ([#213](https://github.com/jonnyzzz/mcp-steroid/issues/213), [#229](https://github.com/jonnyzzz/mcp-steroid/issues/229)).
- `findProjectFile` accepts absolute paths and force-refreshes stale VFS entries — fixing the #1 `execute_code` failure class (35% of eval failures) and the bare NPE it used to surface ([#156](https://github.com/jonnyzzz/mcp-steroid/issues/156)).
- kotlinc diagnostics and stack traces now point at the agent's actual script lines — the line remapping is no longer off by 4 ([#221](https://github.com/jonnyzzz/mcp-steroid/issues/221)).
- `waitForSmartMode` no longer fails hard at its 60-second cap on large projects — a timeout returns a clear "INDEXING IN PROGRESS — keep polling" result so agents wait out long indexing instead of aborting ([#169](https://github.com/jonnyzzz/mcp-steroid/issues/169)). `smart_non_modal` likewise waits out dialog-less modal progress (bounded, default 120 s, with MCP progress notifications) instead of failing instantly, while a real modal dialog still fails fast.
- Project-name resolution no longer takes read actions, so one hung script plus a queued write action can no longer wedge every other MCP tool into 60-second timeouts ([#214](https://github.com/jonnyzzz/mcp-steroid/issues/214)).
- A **31-second UI freeze** attributed to MCP Steroid is gone: `syncDocuments` awaits the recursive VFS refresh off the EDT, with a fail-fast guard so it cannot be reintroduced ([#318](https://github.com/jonnyzzz/mcp-steroid/issues/318)).
- Three `steroid_input` / `steroid_take_screenshot` defects against modal dialogs are fixed — the EDT modality hang, checkbox toggles missing their target, and dialogs reporting the IDE frame's `window_id` ([#309](https://github.com/jonnyzzz/mcp-steroid/issues/309)).
- **Inspections are crash-isolated and cancellable**: a single crashing inspection (e.g. K2's "Cannot compute containing PSI" on kotlinx-serialization plugin-generated declarations) no longer aborts the whole sweep — each tool's failure is reported while the rest keep running ([#93](https://github.com/jonnyzzz/mcp-steroid/issues/93)); `runInspectionsDirectly` tolerates per-file PSI invalid-element failures and returns an additive result with a structured `failedTools` section ([#69](https://github.com/jonnyzzz/mcp-steroid/issues/69), [#94](https://github.com/jonnyzzz/mcp-steroid/issues/94)), and it honors timeouts and cancellation via a cancellable progress indicator on `McpScriptContext` ([#213](https://github.com/jonnyzzz/mcp-steroid/issues/213)).
- The server logs its IDE run mode at startup and emits a WARN plus a client notice when the IDE is headless — headless is unsupported, and now says so ([#212](https://github.com/jonnyzzz/mcp-steroid/issues/212)).

### Execution history in one shared, honest store

Execution history moved out of project `.idea` folders into **collision-safe shared storage under `~/.mcp-steroid/runs`** with atomic directory reservation and full backend provenance recorded per run ([#280](https://github.com/jonnyzzz/mcp-steroid/issues/280), [#433](https://github.com/jonnyzzz/mcp-steroid/issues/433)); execution IDs no longer collide when two executions land in the same second ([#414](https://github.com/jonnyzzz/mcp-steroid/issues/414)), and test JVMs redirect storage to a per-run build directory so running the suite no longer litters your real runs folder. Execution events now route through a bounded serial write queue ([#436](https://github.com/jonnyzzz/mcp-steroid/issues/436)): `output.jsonl` line order is deterministic, a write failure re-raises so the tool call fails honestly instead of ACKing success, overflow is a loud recorded failure, and a cancelled execution flushes its buffered tail under `NonCancellable` so the end of the log is never lost.

### Headless Remote Development backends, bootstrapped by the agent

devrig can now launch a downloaded IDE as a **headless managed Remote Development backend** (`remote-dev-server run`, verified with IntelliJ IDEA Ultimate 2026.2) with MCP Steroid pre-provisioned — resolving the remote-dev launcher, tracking the process via pid markers (with an additive `remoteDevelopmentBackend` flag so devrig can tell backends from desktop IDEs, [#451](https://github.com/jonnyzzz/mcp-steroid/issues/451)), and hardening the lifecycle with single-instance locking and artifact-safety checks ([#411](https://github.com/jonnyzzz/mcp-steroid/issues/411), [#441](https://github.com/jonnyzzz/mcp-steroid/issues/441)).

- Agents can bootstrap the whole **discover → download → start** flow themselves: `open_project` guidance, the managing-backends prompt articles, and the devrig server instructions teach it — distinguishing backend reachability from project routing and Maven/Gradle import readiness — and readiness reporting was refined for frontendless opens ([#449](https://github.com/jonnyzzz/mcp-steroid/issues/449)).
- `devrig mcp` advertises a steroid capability statement at `initialize`, so harnesses that defer tool schemas (like Claude Code) learn the `steroid_*` prefix and provisioning entry points before loading any tool schema ([#428](https://github.com/jonnyzzz/mcp-steroid/issues/428)); the `steroid_*` tool surface is also discoverable by Claude Code's deferred-tool index ([#417](https://github.com/jonnyzzz/mcp-steroid/issues/417)).
- The workflow is documented across the website and validated by clean-machine Claude/Codex Docker scenarios with credential-isolation safeguards ([#411](https://github.com/jonnyzzz/mcp-steroid/issues/411), [#449](https://github.com/jonnyzzz/mcp-steroid/issues/449)).

PhpStorm, RubyMine, DataGrip, RustRover, and MPS join the download catalog — **14 IDE products total**, up from nine ([#430](https://github.com/jonnyzzz/mcp-steroid/issues/430), [#434](https://github.com/jonnyzzz/mcp-steroid/issues/434)) — handling DataGrip's DG-query/DB-install product-code split and reporting explicit unpublished-platform errors for MPS's missing ARM64 builds.

- Downloads retry stalled connections with resume from the partial file, and a baseline-only resolved build now matches the installed full build — `idea-community` no longer fails deterministically *after* an 850 MB download ([#423](https://github.com/jonnyzzz/mcp-steroid/issues/423)).
- Every catalog product's download path is integration-tested end to end against recorded feed payloads, with opt-in live-network and live-download smoke lanes for vendor-feed drift ([#431](https://github.com/jonnyzzz/mcp-steroid/issues/431)).

### `devrig install`: agents, the plugin, and any MCP client

- **New `devrig install plugin`** discovers locally running JetBrains IDEs and installs or updates MCP Steroid over each IDE's built-in REST endpoint — with the IDE's own native install dialog as the consent gate and a read-only `--check` dry-run ([#82](https://github.com/jonnyzzz/mcp-steroid/issues/82), [#391](https://github.com/jonnyzzz/mcp-steroid/issues/391)). `devrig backend` and `devrig project` listings now promote the command — a text hint plus an `installCommand` JSON field — for every running IDE that lacks a compatible plugin.
- Bare `devrig install` prints an overview of all targets with live per-agent CLI detection and a runnable example instead of a usage error ([#277](https://github.com/jonnyzzz/mcp-steroid/issues/277)).
- Flag-less `devrig install devrig` does exactly one thing — re-register the launcher and PATH and print one next-steps message — with no implicit plugin installs, and the script handoff runs under `DEVRIG_JAVA_HOME`, never touching your `JAVA_HOME` ([#398](https://github.com/jonnyzzz/mcp-steroid/issues/398)).
- **New `devrig install config`** prints the manual MCP configuration (stdio JSON plus per-agent mcp-add commands) for clients devrig cannot configure automatically (Cursor, Windsurf, …).
- A missing or unrunnable agent CLI yields friendly install-the-CLI guidance at exit 64 instead of a raw Java stacktrace ([#342](https://github.com/jonnyzzz/mcp-steroid/issues/342)).
- A feature that edited agent config files to re-enable switched-off registrations was added and removed within this release — agents are configured only through their own CLIs, and `docs/install-scripts-contract.md` locks that scope in writing.

### In-IDE onboarding: the plugin offers devrig, and installs it properly

When devrig is missing, the plugin can show a single once-per-IDE-run promotion balloon (after a randomized 12–35 s delay) that explains what devrig is and links devrig.dev tagged with the IDE build — but the balloon sits behind the `mcp.steroid.devrig.widget.enabled` registry key, which is **off by default**: out of the box no startup balloon appears, and the settings page carries the same offer as the default surface ([#367](https://github.com/jonnyzzz/mcp-steroid/issues/367)).

- One click installs devrig by downloading and running the same published install script, **through devrig's own updater machinery** — shared per-pid markers prevent duplicate ~611 MB downloads alongside a concurrent self-update. The install streams the installer's real phases into the progress indicator, and installing devrig registers nothing with any agent — agent registration stays an explicit step.
- Every onboarding notification carries an actionable next step (Retry, Open settings, the exact command), and a single notifications service keeps at most one live balloon per kind, so retries replace rather than stack.
- The release iterated through — and deliberately deleted — a status-bar widget, state monitoring, and an update-offer axis before landing on this one quiet, opt-in surface.

### Settings page rebuilt devrig-first; Marketplace listing rewritten

The settings page is now one transparent top-to-bottom **Devrig** section, renamed **Tools → Devrig — MCP Steroid** ([#394](https://github.com/jonnyzzz/mcp-steroid/issues/394)), plus a collapsed direct-HTTP section explicitly marked deprecated: the install row shows the published one-liner in a copyable field next to an Install button that visibly runs that same script, agent rows are display-only copyable `devrig install <agent>` commands instead of "Checking…" placeholders and background probes, and a collapsed stdio `mcpServers` JSON snippet serves MCP clients devrig cannot register itself. Every displayed path is the real absolute OS-native path, Windows commands use PowerShell's call-operator quoting when the path holds a space, copy actions confirm with a short "Copied" balloon, and the feedback link points at GitHub issues — the one durable channel. The JetBrains Marketplace description was rewritten around the core value — agents get the whole IDE via live Kotlin on the IntelliJ Platform, with devrig as the recommended connection path — dropping stale feature counts and a broken link ([#355](https://github.com/jonnyzzz/mcp-steroid/issues/355), [#395](https://github.com/jonnyzzz/mcp-steroid/issues/395)).

### devrig sessions that fail loudly and never hang

- `devrig mcp` now polls its launching parent's liveness and **self-terminates when orphaned**, so SIGKILL'd agent sessions no longer leave ~250 MB JVMs running for days ([#132](https://github.com/jonnyzzz/mcp-steroid/issues/132)).
- Every production process wait is bounded — a hung agent CLI can no longer hang devrig forever — and timed-out process trees are force-killed ([#387](https://github.com/jonnyzzz/mcp-steroid/issues/387)).
- A malformed stdin line (CRLF, BOM, stray wrapper output) no longer wedges the MCP session: devrig answers with a JSON-RPC `-32700` and a stderr diagnostic, and keeps serving the frames queued behind the garbage — instead of silently dying with exit 0 ([#461](https://github.com/jonnyzzz/mcp-steroid/issues/461)).
- `devrig --debug` actually works again — logging properties are set before logback initializes, restoring verbose stderr and a correct per-pid log file for each process ([#462](https://github.com/jonnyzzz/mcp-steroid/issues/462)).
- `open_project`'s CLI contract now matches runtime behavior: `project_path` accepts an absolute path or one resolved against the caller's working directory ([#471](https://github.com/jonnyzzz/mcp-steroid/issues/471)).
- Windows: a devrig hang during user-PATH registration is fixed — the PowerShell child is no longer spawned with an open stdin and uncaptured output that could block `waitFor` indefinitely ([#150](https://github.com/jonnyzzz/mcp-steroid/issues/150)) — and `devrig status` no longer reports false MCP-registration drift over an unquoted `devrig.cmd` launcher path ([#160](https://github.com/jonnyzzz/mcp-steroid/issues/160)).
- An external review pass (gpt-5.6-sol) then hardened the orphan-detection and missing-CLI fixes.

### Windows support, validated on real Windows

The devrig launcher, managed-backend commands, and the test and prompt-compilation infrastructure now work on Windows dev hosts ([#158](https://github.com/jonnyzzz/mcp-steroid/issues/158)). A dedicated module validates Claude Code MCP-launcher and installer behaviour against real Windows builds, the full plugin hook-form matrix is confirmed on TeamCity and GitHub windows-latest, and the suite is generalized into `:test-integration-agent-launch` running the same launch-form matrix on both Windows and Linux with per-OS assertions ([#255](https://github.com/jonnyzzz/mcp-steroid/issues/255), [#257](https://github.com/jonnyzzz/mcp-steroid/issues/257), [#262](https://github.com/jonnyzzz/mcp-steroid/issues/262), [#269](https://github.com/jonnyzzz/mcp-steroid/issues/269)). A round of fixes found live on the TeamCity Windows agent makes the test suites genuinely Windows-correct — CRLF-normalizing stream assertions, `Path.of(...)`-built path fragments, and an injectable executability probe replacing chmod fixtures that are silent no-ops on NTFS ([#445](https://github.com/jonnyzzz/mcp-steroid/issues/445)) — and the agent CLI test runner kills the whole process tree on timeout with backoff-retried deletes so temp files no longer leak under NTFS lock semantics ([#407](https://github.com/jonnyzzz/mcp-steroid/issues/407)).

### Install scripts: correct next steps, session PATH, honest naming

- Both installers' printed next step is now agent-qualified (`devrig install claude|codex|gemini`) instead of a bare `devrig install` that immediately errors ([#320](https://github.com/jonnyzzz/mcp-steroid/issues/320)), and `install.ps1` prepends the bin dir to the **current session's** PATH so the command works without opening a new terminal ([#275](https://github.com/jonnyzzz/mcp-steroid/issues/275)).
- `install.ps1` works on stock Windows PowerShell 5.1: arch detection no longer crashes under StrictMode or when `OSArchitecture` is unset ([#273](https://github.com/jonnyzzz/mcp-steroid/issues/273)), and the progress bar no longer makes the multi-hundred-MB download crawl ([#274](https://github.com/jonnyzzz/mcp-steroid/issues/274)).
- Both installers close stdin on the `devrig install devrig` handoff, making the install contractually non-interactive under `curl|sh` or `irm|iex`, and output is enforced ASCII-only so legacy consoles render it correctly ([#278](https://github.com/jonnyzzz/mcp-steroid/issues/278)).
- The JDK install directory is named by the vendor JDK version (e.g. Corretto 25.0.3.9.1) instead of the devrig release version ([#362](https://github.com/jonnyzzz/mcp-steroid/issues/362)).

### Prompt corpus: recipes that work on every IDE

- The structured test-run article advertised by the skill index is now actually available on every IDE ([#406](https://github.com/jonnyzzz/mcp-steroid/issues/406)): the Gradle recipe stays gated to IDEA/Android Studio while a new platform-only branch launches an existing run configuration and collects the same structured JSON on PyCharm, GoLand, WebStorm, CLion, RubyMine, and DataGrip — and the recipe excludes processes that existed before the launch, so a pre-existing run of the same configuration is never reported as this launch's result or destroyed on timeout.
- The lsp/completion recipe lists completion contributors via the public extension point instead of a deprecated API, compiling warning-free on both 2026.1 and 2026.2 ([#409](https://github.com/jonnyzzz/mcp-steroid/issues/409)).
- Verification primitives now distinguish "clean" from "did not run": inspection sweeps report non-PSI inputs as failures, and four new prompt recipes give agents a canonical result vocabulary for structured post-edit verification ([#142](https://github.com/jonnyzzz/mcp-steroid/issues/142)).

### Under the hood: build, CI, and shared internals

- The build moved to **Gradle 9.6.1** with the IntelliJ Platform Gradle Plugin at 2.18.1, resolving every resulting deprecation ([#371](https://github.com/jonnyzzz/mcp-steroid/issues/371)); a BuildFetch remote build cache layers on top of the local cache (CI-only pushes, a verified read-only public token as the zero-setup contributor fallback, and release builds compiling entirely from source with all caches disabled); on TeamCity, public Maven hosts route through the JetBrains cache redirector, ending Maven Central 429 rate-limit failures.
- `buildPluginOnCI` now builds and publishes the devrig release binary zip alongside the plugin zip ([#252](https://github.com/jonnyzzz/mcp-steroid/issues/252)), and a new `deployDevrig` task replaces `deployNpx` ([#376](https://github.com/jonnyzzz/mcp-steroid/issues/376)).
- The [#412](https://github.com/jonnyzzz/mcp-steroid/issues/412) burn-down took the main Docker IDE matrix from 15 failures to green and the CompatTests lane to 9/9, with a new lane split keeping the main smoke matrix fast; installer integration tests pre-bake their tooling into digest-pinned images, cutting the suite from ~10 minutes to 44 seconds ([#443](https://github.com/jonnyzzz/mcp-steroid/issues/443)); Gemini missing-key tests report SKIPPED honestly on TeamCity instead of silently passing without running ([#408](https://github.com/jonnyzzz/mcp-steroid/issues/408)); version-lane assumptions became a deterministic injected-version matrix ([#410](https://github.com/jonnyzzz/mcp-steroid/issues/410)).
- A new IJ-free **devrig-common** module holds everything the devrig CLI and the IDE plugin share — the `~/.mcp-steroid` home layout, update coordination, launcher tooling, PID-marker wire types, and the installer-script download — with an audit confirming no hand-joined paths remain and forbidden-import/CI guards keeping the module minimal ([#444](https://github.com/jonnyzzz/mcp-steroid/issues/444)).
- The DPAIA arena and experiments dashboard got fairer and deterministic: the harness validates MCP execution against the task's own project ([#251](https://github.com/jonnyzzz/mcp-steroid/issues/251)), broken scenario fixtures were repaired ([#447](https://github.com/jonnyzzz/mcp-steroid/issues/447)), and a new `:experiments-report` dashboard computes every verdict deterministically from run data. Design records land the validated LIST/CALL recipes for IntelliJ's native MCP tools ([#352](https://github.com/jonnyzzz/mcp-steroid/issues/352), [#353](https://github.com/jonnyzzz/mcp-steroid/issues/353)) — groundwork for a future release.

### Known issues

- [#78](https://github.com/jonnyzzz/mcp-steroid/issues/78) — `steroid_execute_code` on a **Windows-side IDE opening a WSL-hosted project** remains open. 0.102's in-process compilation removes the kotlinc subprocess spawn the report traced, but the change has not yet been validated on a Windows+WSL environment, so the issue stays open; the `mcp.steroid.storage.path` registry-key workaround remains documented.
- [#259](https://github.com/jonnyzzz/mcp-steroid/issues/259) — `devrig install plugin` targets **running** IDEs only; installing into closed IDEs and staging an update for the next restart is recorded as the follow-up design (live in-process hot-swap was researched and ruled out).
